# PROJECT SYNC — 2026-11-03 (ChatGPT / Codex / Claude 공통 기준)

> **상태:** 사용자·ChatGPT가 합의한 최신 연구/작업 방향. 이 문서는 기존 구현 결과를 소급 수정하거나 신규 모델·실증 효과의 완료를 뜻하지 않는다. 우선 읽을 파일: 이 문서 → `outputs/AGENT_HANDOFF.md` → 기존 V1·Batch01/02·제출 초안. 충돌 시 **기존 실험의 완료 사실은 실제 코드·결과를 우선**, **앞으로의 방향·우선순위는 이 문서를 우선**한다.

## 1. 최종 목표와 이번 방향 전환

롯데 AX Challenge 2026, 롯데케미칼 첨단소재 End Customer 수요예측 AI 기획. 제출 마감 기준은 **2026-11-04 23:59 KST**(2026-10-30 보존된 공식 기록; 제출 전 현행 화면 확인 필요). 필수 서술 3개 최대 3,000자, 선택 포트폴리오.

- **처음의 연구 질문:** 고객 주문에 재고·묶음 발주·리드타임이 섞여 실제 PC/ABS 소비와 달라질 수 있다. 소비를 복원하여 미래 FCST에 활용할 수 있는가? 채찍 효과는 **가설**, 실제 롯데의 사실이나 출제 의도가 아님.
- **사용자의 핵심 재판단:** 실제 롯데도 고객 B의 전체 공급사 주문·입고·재고·BOM·경쟁사 공급비중을 확보하지 못할 수 있다. 따라서 내부자료 의존 역산만 고집하지 않고 **다양한 공개·허가된 외부 산업활동 지표를 단계적으로 수집·결합해 실제 수요 방향의 보조 신호를 추정**하는 접근을 추가한다.
- **새 제안의 정확한 위치:** 'V1을 폐기'가 아니다. V1은 데이터 식별 한계와 단일 대리지표의 실패 가능성을 보인 **합성 개념검증**으로 보존한다. 외부지표 수집과 다변량 신호 결합은 **V2 확장 가설/설계 단계**다.
- **목표값을 혼동하지 말 것:** 고객 B의 PC/ABS 실제 소비 `C`, 산업 활동 기반 수요 신호/지수, 롯데 자사 주문량 `O_LC`는 각각 다르다. 공개 생산·수출 통계만으로 **고객별 실제 C(톤)** 또는 채찍 효과 크기·원인·예측 개선을 입증하지 못한다. 실제 주문/소비 등 정답이 확보되면 별도 시점 분할 검증한다.
- 범위 예시: 자동차용 PC/ABS, 가상 완성차사 A → 가상 가공사 B → 롯데. **이 가상 연결이 실제 고객사 거래 관계나 채택 소재를 나타내지 않음.** KAMA 생산·수출은 국내 산업 집계라 A/B 소비에 직접 대응하지 않는다.

## 2. 구현 완료 사실 (V1, 변경 없이 유지)

- 표준 라이브러리 Python CLI `work/prototype/experiment.py`, 테스트 7개, 합성 48개월×20시드×2조건×3공급비중×3방법, 예측 4,320행.
- 자사 주문과 1개월 늦게 공개된 합성 생산 대리지표를 사용한 scalar 칼만 필터, 최근 3개월 주문평균·직접활용·상태추가 비교.
- 공급비중 .45 합성 기본 조건 MAE(톤): 49.872 / 32.495 / 28.282. 대리지표 +50% 오염 조건: 49.872 / 42.127 / 47.447(상태 추가 악화). 명목 95% 상태 단독 구간의 기본 포함률 45%, 오염 21.7%: **실무용 신뢰구간 아님**.
- Claude 독립 리뷰의 추가 진단: 2개월 주문 평균 33.6톤, 최신 대리지표 하나만 사용 23.3톤. 기존 기준모델 선택과 원단위/공급비중 참값 일치가 유리하므로 **칼만 필터 고유의 정확도 우월성은 입증되지 않음**.
- 현재 구현은 규칙 기반 검증·추정·보고 CLI로, **LLM/자율 Agent가 동작한다는 뜻이 아님**. ChatGPT, Codex, Claude 사이 자동 연결도 없다.

## 3. 외부 지표 증분 확장 (V2 데이터 단계)

- 사용자는 'Agent를 이용해 장기적으로 수십 개 지표를 관리하되 조금씩 추가'하는 방식을 선택. **수집·정제·품질·판본·시점 관리의 자동화 규모**와 **예측모형에 실제 채택되는 변수 개수**를 분리한다.
- Batch01: KAMA 확정 산업동향 HTML을 수동 전사한 **불연속 8개월(2025-09~12, 2026-05~06, 2026-08~09)** 생산량/수출량.
- Batch02: 2026-01 산업통상부 공식 HTML 값, 2026-02~03 KAMA 잠정 HTML 값 **3개월** 별도 CSV. 총 **11/13개월 값 확인**이나 출처·잠정/확정 판본 불일치로 **학습용 연속 확정 시계열 아님**.
- 2026-04·07 정확한 동일판본 확정치 미검증. KAMA XLSX 원본 다운로드·셀별 대조 실패. **24~36개월 연속 원본 미확보**, **실제 고객 C/O_LC와 연결된 학습/평가 데이터 없음**.
- 현재 최초 두 지표: 국내 자동차 월별 생산량과 수출량. 둘은 서로 중복 가능하고 **선행 신호라는 사실은 입증되지 않음**. 실제 지표의 지연·공표 시점에 따라 동행/후행일 수 있다. 향후 KOSIS 생산·재고, BSI 신규수주, 환율, 원료/소재가격 등은 **후보**일 뿐 아직 수집·검증 완료 아님.
- `period`(관측 기준월), `publication_date`, `available_at`, `vintage`(잠정/확정/수정), 단위, 범위, 지표 ID, 원본 URL을 보존한다. 공개일만 알고 공개 시각을 모르면 보수적인 다음날 사용 규칙을 따른다. 결과를 맞추려고 과거 시점에 미래 공표치를 넣지 않는다.
- 먼저 공식 원본·연속기간 확보와 판본 정합성 검증. 이후 **새 지표를 하나씩 추가했을 때 검증 대상(산업지표 자체 또는 실제 확보된 주문/소비)의 예측력이 높아지는지** 비교. 정답 부재 시 추가 '예측력' 주장 금지.

## 4. Agent 설계의 역할과 정직한 구현 표기

개념상 워크플로: 지표 소스 탐색/등록 → 허가된 접근으로 수집 → 단위·수정판·공표시점 확인 → 정규화/중복검사 → 개별 지표 가설/추가 가치 평가 → 산업 기반 신호 추정 → 고객별 주문과의 비교(실제 허가된 주문 있을 때만) → 불확실성·오염 감지 → 담당자에게 근거/확인 질문 제시.

- 이 워크플로는 **제안된 Agent 아키텍처**. 현재 자동 수집 Agent·LLM 오케스트레이션·웹 배포는 구현하지 않았다. Codex를 활용해 자료를 모으는 과정과 제품 내 자동 Agent를 혼동하지 말 것.
- 대량 지표 수집이 가능해도 표본이 짧으면 과적합·공선성·시점 누수 문제가 생긴다. 수집 가능 = 채택 필요 = 예측력 입증이 아니다.
- 다변량 상태공간·동적요인 모형은 **연구 후보**, 아직 합성 V1 코드에 구현되거나 외부 실측으로 검증되지 않았다. 모델의 잠재 수요와 공급비중·발주 편차를 모두 자유롭게 설정하면 여전히 비식별될 수 있다.

## 6. 역할과 협업 규약

| 주체 | 맡은 역할 |
|---|---|
| 사용자 | 연구 질문·우선순위와 최종 선택, 실제 경험·지원서 문장 확인, 로컬 실행/최종 제출 |
| ChatGPT (orchestrator) | 단일 기준 문서·단계 결정·지시·충돌 조정. 직접 확인한 사실과 보고된 사실 구분 |
| Codex (primary executor) | **명시된 범위만** 실제 수집/코드/품질검증/문서·커밋 수행. 원본 출처/판본/누수와 성공·실패 증거 기록. 독자적으로 연구 범위 확대 금지 |
| Claude (independent reviewer) | Codex 결과를 복창하지 말고 독립 검산·재현·실패 사례·공식 근거·제출 정직성 검토. 검토 시 원본 수정 금지 |

**Agent 간 직접 자동 통신 없음.** 사용자가 각각 전달한다. 모든 작업자는 새 작업 전 `git status`, `git log -1`, 원격 최신 여부를 확인하고 로컬 변동이 있으면 강제 리셋/덮어쓰기 금지.

## 7. Codex·Claude 즉시 동기화 행동

**동기화 완료 조건:** 두 도구가 모두 같은 최신 방향(외부 지표 점진 확장 + V1 합성 보존), 두 지표 현황(8 확정 + 3 혼합, 결측 04/07, XLSX 실패), 구현과 미구현, 마감 우선순위를 이해했다고 응답한다.
