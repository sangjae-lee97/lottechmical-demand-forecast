최신 범위는 현재 StatisticItemList의 BD·각 업종 월별 END_TIME을 확인하고, **기준선 시작월부터 max(기준선 마지막월, 공식 항목 메타데이터의 종료월)**까지 요청한다. 과거 기준선 구간을 조용히 줄이지 않는다. 메타데이터는 요청 범위 상한의 근거이며, 실제 확보 마지막월은 StatisticSearch의 유효 TIME으로 판단한다. 미래 월을 추정해 행을 생성하지 않는다.

이번 메타데이터 종료월은 두 업종 모두 2026-11이었다. StatisticSearch 공식 페이지 범위는 업종별 **1~20 / 21~36**, 모든 응답 총행수·페이지별 수신행수·최종 합계가 일치했다. 공통월 범위·중복·코드·명칭·단위·숫자·월 인코딩 검사를 통과했다. 원본 UNIT_NAME의 null도 보존하며, 별도 의미 단위는 이전 공식 BSI 설명에 근거한 지수다.

## 2. 실제 비교 결과

| 분류 | 자동차 C3000 | 제조업 C0000 | 합계 |
|---|---:|---:|---:|
| UNCHANGED | 36 | 36 | **72** |
| NEW_TARGET_MONTH | 0 | 0 | **0** |
| HISTORICAL_VALUE_CHANGED | 0 | 0 | **0** |
| MISSING_OR_REMOVED | 0 | 0 | **0** |
| INVALID_OR_UNVERIFIED | 0 | 0 | **0** |

의도적 요청 창 밖 분류 OUTSIDE_QUERY_WINDOW도 0건이다. 로컬 `diff.json`은 월·업종·항목에 대응하는 72개 비교를 보존한다. 변경이 있으면 CLI는 해당 월·업종·유형을 개별 관측값 없이 출력한다. 숫자 문자열 `10`과 `10.0`처럼 표현만 다른 것은 Decimal로 같은 값으로 비교한다. INVALID_OR_UNVERIFIED 건수는 검증 이슈 수이며, 여러 이슈가 한 월에서 생길 수 있다.

이번에는 변경이 없어 `review_required=false`다. 수집 정상 여부와 모델 입력 승인 여부는 별도이며 **model_input_promoted=false**다. 이전에 PDF와 대조한 기준선의 최근 두 월×두 업종 **4개 값도 이번 조회와 일치**했다. 이는 보존된 기준선/PDF 확인 기록과 값이 일치한다는 뜻이며, 새 PDF 판본이나 정정 이력을 다시 조사했다는 뜻은 아니다.

향후 같은 월 값이 달라져도 HISTORICAL_VALUE_CHANGED는 **이전 조회값과 달라졌다는 탐지**다. 공식 정정으로 단정하지 않으며 원문·정정 공지·판본 조사가 필요하다. 데이터가 정상이어도 자동 학습·예측·실적 채점에는 연결하지 않는다.

## 3. 시점·판본 계약

신규 정규화 행에는 `forecast_target_month`, `survey_month=t-1`, `observed_at`, `publication_date`, `available_at`, `vintage_verified`를 분리했다. observed_at은 해당 업종의 수신 완료 시각이며 페이지별 수신 시각도 requests에 따로 남긴다.

- 자동차 수신 완료: `2026-11-04T09:07:25.939928+09:00`.
- 제조업 수신 완료: `2026-11-04T09:07:26.671765+09:00`.
- 두 시각은 **우리 시스템의 조회 시각**이다. 한국은행의 공식 공표·최초 이용 시각으로 쓰지 않는다.
- 이번 API가 제공하지 않은 공표일·이용 가능일은 **신규 72행 모두 null**, `vintage_verified=false`로 보존했다. 이전 기준선의 알려진 공표일을 새 조회 판본의 공표일로 자동 복사하지 않는다.
- 2026-11 목표월은 2026-10 조사 표본개편·KSIC-11 경계 플래그를 유지한다. 이후 월에는 해당 개편 이후라는 별도 플래그를 둔다. BSI를 해당월 생산 실적이라고 해석하지 않는다.

이 판본 관리는 조회 이력을 남기는 기능이다. 모든 과거 공식 최초 공표판을 복원하거나 시점 검증을 끝낸 기능은 아니다.

## 4. Append-only 보관과 실패 처리

실제 로컬 저장 위치:

```text
work/data/local_only/round11_snapshots/20261104T090724027444_cd96f70034a7/
  baseline/normalized_snapshot.json, manifest.json
  raw/                         # 수신 원문 바이트 5개
  normalized.json              # 이번 조회 72행, 시점/개편 플래그
  diff.json                    # 기준선과 월·업종별 비교
  source/                      # 실제 실행 스크립트·키 로더 사본
  manifest.json, manifest.sha256
```

매 실행은 실제 시각+무작위 ID로 새 폴더를 배타적으로 생성하고, 모든 파일은 `xb`로 새로 기록한다. 기존 판본을 교체·삭제하거나 최신 파일로 덮어쓰지 않는다. **변화 없는 조회도 이번 판본으로 별도 보존**한다. 현재 비교 기준은 해시로 확인한 Round 07-C 스냅샷이며, 직전 실행을 자동으로 승인 기준선으로 승격하지 않는다. 첫 기준선이 비어 있을 때의 비교는 합성 테스트로 검증했지만, 운영 CLI에서 기존 기준선이 없거나 해시가 다르면 중단한다.

네트워크/HTTP 오류·키 누락·응답 형식/페이지 불일치·중복·잘못된 코드 등은 실패 상태와 비정상 종료 코드로 기록한다. 월 누락·업종 범위 불일치도 보간·0 대입하지 않고 격리한다. 실패 원문은 기존 raw 파일을 남긴 채 해당 실행의 **quarantine/raw/**에 별도 사본을 기록하고, 검토 마커를 남긴다. 키 또는 키 포함 URL을 되돌려주는 응답은 저장 전 차단하여 원문을 보존하지 않는다. 리다이렉트도 자동 추종하지 않는다. 파일 저장 자체가 실패하면 부분 폴더가 남을 수 있으나 정상 수집으로 표시하지 않는다.

명시적 CLI 수동 실행이며, 규칙으로 수집→검증→차이 분류→검토 필요 플래그 표시를 연결한다. 스케줄러·상시 감시·메일/Slack 알림·LLM·자율 Agent는 미구현이다. KOSIS는 기존 공개 화면 SDMX 수동 확보 경로를 유지하며, 자동 수집이나 선택적 import 모드를 이번에 추가하지 않았다.

## 6. 테스트·오프라인 재검증·봉인 무결성

합성 fixture **9개 테스트 통과**:

1. 첫 기준선 비교, 동일 자료 재조회, 숫자 표현만 달라진 경우.
2. 신규 월 추가와 기존 동일월 값 변경, 공식 정정/모델 승격으로 오해하지 않는 상태.
3. 결측과 의도적 요청 창 축소의 구분, 결측 판본 격리.
4. 중복·잘못된 코드·업종별 월 범위 불일치·비유한 수치 거부.
5. 다중 페이지의 공식 행 범위·원문 바이트 해시·총건수 불일치 검출.
6. HTTP 예외·키 반사 응답·리다이렉트의 차단과 키/URL 비노출.
7. 반복 실행별 새 폴더, 이전 실행·기준선·합성 Round 10 폴더 불변.
8. 오프라인 검증에서 API/키 파일 접근 0회, 아카이브 변조 검출.
9. 키 누락 시 API 호출 없이 실패 기록.

실제 API 실행 후 **오프라인 검증 모드**를 실행해 manifest·11개 파일 해시와 정규화/비교 결과 재연을 통과했다. 이 모드는 키를 읽거나 네트워크를 호출하지 않고 파일도 변경하지 않는다. 실패 아카이브의 해시가 맞더라도 원 수집의 실패 상태·비정상 종료 코드를 그대로 반환하며 데이터 승인으로 바꾸지 않는다.

실제 수집 전후 Round 10 폴더 **22개 파일**의 내용 해시가 모두 같았다. 예측을 재계산하거나 채점하지 않았다.

- 예측 canonical SHA: `a1ffff49a5e39c89be5989bfb45387fece6e010a6de611ea8cfa4a48238f36b7` 유지.
- 전체 파일명/내용 해시 목록의 tree SHA: 전후 모두 `f667fd1a5226e546b5867225ff68c9b3dac2c6b041a0e6b4d7e9e92d3ad14e3a`.
- 기존 V1·Round 07~10 코드·결과·지원서와 로컬 미추적 감사 파일은 보존했다.

## 7. 실행 방법과 Claude 검토 자료

프로젝트 루트에서 새로운 판본을 수집할 때만:

```powershell
python -X utf8 work/research/round11_ecos_snapshot_pipeline.py --collect
```

이번 판본을 API 재호출 없이 검증하려면:

```powershell
python -X utf8 work/research/round11_ecos_snapshot_pipeline.py --validate-run 20261104T090724027444_cd96f70034a7 --expected-manifest-sha256 5f189a02ecbbd3bb24fea924ef8a0ca895a3018db8a19e015c7df2a0c40d33c6
python -X utf8 -m unittest discover -s work/research -p test_round11_pipeline.py -v
```

키가 없으면 실제 값을 대화로 보내지 않고 로컬 `.env`에 `ECOS_API_KEY=발급받은값` 형태로 설정한다. `--collect`는 매번 새 API 조회와 새 실행 폴더를 만들며, 기존 실행 확인에는 `--validate-run`을 사용한다. 공개 manifest SHA를 외부 기준으로 지정하면 로컬 sidecar만 신뢰하는 것보다 강한 변조 대조가 가능하다. 해시와 호스트 조회 시각이 공식 공표 시각이나 공인 타임스탬프 증거인 것은 아니다.

Claude는 새 코드·합성 테스트·이 보고서와 로컬 run의 manifest/raw/normalized/diff/source를 검토할 수 있다. 우선 쟁점은 페이지/코드 검증, 관측 시각과 공표 시각 분리, 변경 분류와 격리, 키 비노출, 원본 바이트 보존 및 봉인 불변이다. Claude를 자동 호출하지 않았다.

GitHub 공유 대상은 새 파이프라인·테스트·이 집계 보고서 3개다. 인증키·원문·정규화/비교의 개별 관측값은 로컬 제외 경로에만 보관한다. 최종 Push 커밋 SHA는 완료 메시지로 전달한다.
