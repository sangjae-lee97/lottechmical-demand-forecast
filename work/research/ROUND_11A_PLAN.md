# ROUND 11-A — ECOS BSI 신규 스냅샷 감지·판본 보존 파이프라인

작성: 2026-11-04 KST / ChatGPT Orchestrator
상태: **실행 지시서. 아직 자동 갱신·상시 감시/알림·LLM Agent가 구현되었다고 주장하지 않는다.**

## 목표

한 번 성공한 ECOS 수집을 **재현 가능한 반복 워크플로**로 바꾼다. 새 자료가 생겼는지 탐지하고, 이전 조회 판본을 덮어쓰지 않고 보존하며, 변경 근거를 남겨 사람에게 검토 요청하는 **규칙형 CLI 수집·검증 파이프라인**이 Round 11-A 목표다.

기존 Round 10의 12개 봉인 예측과 SHA `a1ffff49a5e39c89be5989bfb45387fece6e010a6de611ea8cfa4a48238f36b7`는 불변. 이것을 새로운 데이터 수집과 결합해 **자동 재학습·자동 채점하지 않는다**.

## 입력 및 사실 계약

- ECOS 기존 코드: `StatisticSearch`, `512Y008` 업종별 BSI **전망**, `M`, `BD` 신규수주 전망, 자동차 `C3000`와 제조업 전체 `C0000`.
- 기존 로컬 베이스라인: `work/data/local_only/round07c_ecos/normalized_snapshot.json`, 2023-12~2026-11 36개월씩. 이 원본·기존 manifest의 해시를 확인하고 **읽기만** 한다.
- 인증키는 루트 `.env`의 `ECOS_API_KEY`. 값/인증키가 포함된 URL·예외·응답 원문을 콘솔/보고서/Git에 노출 금지. 샘플키로 대체하거나 제한 우회 금지.
- `TIME`은 BSI **전망 대상월**. `survey_month = forecast_target_month - 1`. 생산 원지수의 해당월 실적과 혼동하지 않는다.
- 조회 시각 `fetched_at` 또는 `observed_at`은 **우리 시스템이 조회한 시각**일 뿐 한국은행의 `publication_date`, `available_at`, 최초 공표판 `vintage`가 아니다. API에 공표/수정일이 없으면 null로 둔다.
- BSI 전망 대상월 **2026-11부터 2026-10 조사 표본개편/KSIC-11 전환 플래그** 보존. 현재 비교에 포함될 기존 2026-10/11 공식 PDF 대응값을 검사할 수 있으면 검사하되 공식 이전 판본이 보존된 입력을 임의 최신화하지 않는다.

## 구현 범위 — Codex primary executor

1. 기존 `work/research/collect_round07c_ecos.py`, `verify_round07c_ecos.py`의 공식 엔드포인트·파싱 로직을 재사용하거나 별도 모듈로 분리한다. **Round 07-C/10 원본과 봉인 코드는 변경하지 않는다.**
2. 새 스크립트 예: `work/research/round11_ecos_snapshot_pipeline.py`. 명시적 일회 실행 CLI로서 **정식 인증 API**에서 두 업종의 최신 가용 월별 범위를 조회. 이전 36개월 이상이 겹치도록 조회 기간을 정하고, 페이지 분할과 공식 전체행 수 일치를 재검증한다. 기간을 현재 API 응답의 유효 마지막월로 판단하며 미래 월을 추정 생성하지 않는다.
3. 원본 응답은 바이트 SHA-256과 함께 `work/data/local_only/round11_snapshots/<run_id>/`에 **매 실행 별도 폴더(append-only)**로 저장. `run_id`는 충돌 없이 생성하고 **기존 파일 교체/삭제 금지**. 입력 파일·원 API 응답/파싱 결과·검증 메타데이터·파이프라인 실행 소스 SHA를 manifest로 보관. 의존성과 공식 출처/주기/단위/선택 코드도 기록.
4. 베이스라인 스냅샷과 새 스냅샷을 월·업종·항목 코드 기준으로 비교한다. 분류:
   - `UNCHANGED`: 공통 월의 값 일치, 새 월 없음.
   - `NEW_TARGET_MONTH`: 아직 없던 전망 대상월 추가.
   - `HISTORICAL_VALUE_CHANGED`: 과거 동일 월 수치 달라짐. **공식 정정이 확정된 것이라고 단정하지 않고, 원문 확인·수정 이력 조사 대상으로 분류**.
   - `MISSING_OR_REMOVED`: 이전 값이 새 조회 창에서 빠짐(의도적 창 축소와 구분) 또는 기존 대상 월 누락.
   - `INVALID_OR_UNVERIFIED`: 공식 코드/형식/값/월·페이지·중복 불일치 등 검증 실패.
   - 두 업종의 동일 타깃 월 범위 불일치는 경고 또는 실패 처리; 조용히 결측 보간/0 입력 금지.
5. API의 현재 판본과 이전 조회 판본을 동시에 보존하고, 데이터/검증이 정상이라고 해도 **자동으로 모델 입력 '시점 검증 완료' 표시하지 않는다**. 각 기록의 `observed_at`·`publication_date`·`available_at`·`vintage_verified` 별도 필드로 유지. 공표일/판본 미확인은 명시.
6. 실행 결과에 변화 유무, 월/업종별 **변경 건수**와 유형, 대상월 범위, 해시, 조사월/전망월, KSIC 개편 플래그를 출력. 공식 개별 관측값은 공개 보고서/로그에 포함하지 않는다. 설명을 LLM이 임의 수치로 생성하거나 기존 모형을 재훈련시키지 않는다.
7. 네트워크 오류·인증키 누락·HTTP 비정상·페이지 수 불일치·판본 충돌 시 원인을 키 없이 보고하고 **실패 상태로 종료**, 성공으로 위장하지 않는다. 실패한 원본도 가능하면 `quarantine`로 별도 보관하고 승인된 기준선으로 승격하지 않는다.
8. 테스트는 **공식 수치를 포함하지 않은 합성 fixture**만 이용해 오프라인 실행: 첫 baseline / 동일 자료 재조회 / 새 대상월 / 같은 월 수정값 / 월 누락·중복 / 잘못된 분류 / 인증키·URL 로그 비노출 / 이전 스냅샷 불변 / Round10 봉인 파일 불변. 재실행·유효한 `dry-run`/검증 모드에서 외부 API 호출이 발생하지 않도록 테스트.
9. 파이프라인은 **수동 1회 실행까지 검증**하면 충분. 스케줄러·메일·Slack·알림·자율 에이전트·LLM 연동은 별도 명시적 후속 단계이며 이번에 구현했다고 표현 금지. 공식 API 호출을 과도하게 반복하지 않는다.

## KOSIS의 별도 경로(범위에 포함하되 억지 자동수집 금지)

- 기존 공식 KOSIS `101 / DT_1F02001`에서 `C222` 플라스틱 제품·`C303` 자동차 신품 부품 생산지수는 공개 화면에서 SDMX GenericData/DSD를 내려받은 **수동 확보 경로**다.
- KOSIS는 ECOS API와 다름. 공식·허용된 자동 접근 경로와 키 발급 여부를 확인하기 전 KOSIS 웹 화면을 무인 스크래핑하거나 URL/인증 제한 우회 금지.
- **선택:** 수동 다운로드 파일을 `work/data/local_only/round11_kosis_inbox/`에 넣으면 동일한 해시·업종/항목·개월 검증 및 append-only 판본 비교를 하는 `--import-kosis` 모드를 범위 여유가 있을 때 구현 가능. 실제 수집 자동화와 수동 파일 검증/가져오기를 구분한다. 범위가 늘어나면 ECOS 기능 우선 완료.
- 새 생산 실적 `2026-10/11`이 발견되더라도 Round 10 봉인 파일을 **열어서 수정하거나 재생성하지 않는다**. 별도 채점 프로토콜을 승인하기 전 점수 계산도 금지.
