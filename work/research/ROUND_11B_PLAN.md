## 2. ROUND 11-B 목표

**사람이 검토·승인한 공식 스냅샷을 명시적으로 기준선으로 승격하고, 이후 조회는 최신 승인 기준선과 비교**하되 모든 이전 판본·변경 이력과 원본 해시를 보존한다.

### A. 승인 레지스트리

- 새 로컬 전용 `work/data/local_only/round11_registry/` 아래 append-only 승인 기록과 작은 current pointer를 둔다.
- 최초 기준선은 Round 07-C 원본 SHA, 출처 코드/기간/승인정책과 함께 부트스트랩. 임의로 이미 사용자 승인했다고 쓰지 말고 기존 프로젝트 기준선이라는 상태를 구분.
- 승격 후보는 사전 수집된 검증 성공 run ID + **외부 공개 manifest SHA**로 식별. 원본 manifest·normalized 파일·비교결과는 해시 확인 후 사용한다.
- 승격에는 **명시적 인간 검토 결정**이 있어야 한다. 검토자/검토일/결정 이유/검토 범위/확인된 공표판 근거/판본 미확인 사항을 기록. 자동 승인/암묵적 승격/오류 격리 run 승격 금지.
- 기존 내용 대신 'latest' 파일을 통째로 덮어써 과거 승인 기록을 잃지 않는다. 포인터 갱신은 검증 후 원자적으로 처리하고 승인 로그는 append-only 유지. 첫 단계에서는 CLI 대화형 사용자 입력이 아니라 로컬 검토 승인 문서 등을 명시적으로 인자로 받아 검증하는 설계를 선호.
- `observed_at`·`publication_date`·`available_at`·`vintage_verified`를 별개 필드로 보존. **인간 승인은 공식 과거 최초 공표판의 검증을 의미하지 않는다**.
- 이전 승인/스냅샷과 현 승인 판본이 달라지면 월별 변경 건수와 종류를 남긴다. 실제 숫자는 공개 repo에 넣지 않는다.

### B. 수집 파이프라인과의 연계

- Round 11-A 수집·정규화·격리 규칙은 유지.
- 새 승인 기준선 선택 기능을 추가한다면 `--baseline-id`나 별도의 `--registry-current`처럼 **명시적**이며 재현 가능한 원본 SHA 참조를 사용.
- 검토 전에는 기존 기준선/최신 조회 run을 절대 자동 바꾸지 않는다. 다른 날짜 실행에서도 같은 승인 ID를 지정하면 같은 판본에 대한 비교가 재현돼야 한다.
- 신규 월, 과거 값 변경, 수록구간 축소, 개편 이후 월 등을 그대로 분류. 정상 유효성 검사와 **비즈니스 승인**은 별도.
- 변경에 공식 정정이 포함돼 있는지는 사람/출처로 확인할 때만 기록; 단순 수치 차이를 공식 수정이라고 단정 금지.
- 스냅샷 조회를 잘 수행해도 자동 모델 재학습, V1·Round 08-B 점수 재기록, Round 10 봉인 변경/채점 금지.

### C. 테스트·실증

- 합성 테스트: 승인 성공/중복 승격·서로 다른 원본 해시/오류 격리 run 거부/승인 로그 변조 감지/선택한 과거 승인 ID로 동일 비교/새 승인을 통한 NEW_TARGET_MONTH의 UNCHANGED 전환/키·원본 수치 누출 차단.
- Round 11-A 9개 테스트 재실행. 실제 기존 run은 **읽기만 검증**, 불필요한 API 재호출 금지.
- 현재 조회된 72건 동일 run은 승인할 이유가 없으므로 최초 승인 등록/검토 프로세스만 dry-run/합성으로 점검하고, 임의로 '승인 완료'라고 기록하지 않는다.
